게임 규칙 설계 — 첫 설계

설계 승인 작성일: 2026-10-27

요약

마스터 6명이 1시간 턴으로 5일(120턴) 동안 겨루는 서버 턴제 전쟁 시뮬레이션의 게임 규칙을 정했습니다.

마스터는 프롬프트 대신 세팅값(boolean·1~5)과 영웅 구성으로 참모 AI를 조율합니다. 참모는 턴마다 한 번 호출되어 영웅 5명의 임무·거점 운영·외교를 정하고, 메모와 전쟁 일지를 남깁니다.

영웅은 1~5성 등급이 BM의 축이고, 유대 승급과 숨은 아웃라이어가 pay-to-win을 막습니다. 모델 격차는 보고서 길이 예산 계수로 조정하고, AI 운용에 닿는 것은 팔지 않습니다.

다음 단계로는 서버·계정 없이 규칙 엔진, 빠른 턴 모드, 봇만으로 가설 A~E를 확인하는 시뮬레이션 프로토타입을 권장합니다.

한 턴의 흐름

정각 처리→ 정기 호출 1회→ 계획 공개→ 검토 약 55분→ 5분 전 마감→ 다음 정각 처리
계획 공개→ 세팅 변경 + 수동 재계획(하루 3회)→ 새 계획

정각 처리 순서: 이동 → 조건 판정·반응 → 전투 → 생산·성장 → 외교 정산. 처리 중에는 AI를 호출하지 않습니다. 실패한 호출은 재시도 없이 규칙 참모로 대체하므로 마스터당 매치 최대 135회로 고정됩니다.

참모 AI와 세팅

세팅값예시작동
성향1~5공격성, 확장 욕구, 위험 감수, 동맹 신의프롬프트 방향 문구
지침boolean희귀 자원지 우선, 약한 상대 우선알림만
안전장치boolean·1~5수도 최소 수비, 동맹 공격 금지게임이 강제
정보 구성on/off + 상세도적 이동 기록, 외교 이력, 탐험 보고, 메모 길이보고서 길이 예산 안에서 선택
영웅별 상시 명령boolean·1~5수도 방어 전담, 후퇴 기준, 원정 허용게임이 강제

AI 지휘관 장치

  • 참모 메모: 다음 호출의 자신에게 남기는 턴 간 기억
  • 조건부 명령: 임무 하나에 조건 하나, 추가 호출 없이 턴 처리 중 반응
  • 전쟁 일지: 판단 근거. 상대 것은 매치 종료 뒤 공개
  • 강제 규칙 최소화: 안전장치는 소수만

명령 확정 순서

  1. 마스터 직접 수정
  2. 제약(상시 명령 + 안전장치, 함께 적용)
  3. 참모 계획

잘못된 항목은 그 항목만 규칙 참모가 대체하고, 형식이 통째로 깨지면 계획 전체를 대체합니다.

영웅

계정에 남는 것 / 매치마다 초기화

항목지속
보유 영웅, 고유 특성, 등급, 유대, 숨은 성장 계수계정 유지
레벨, 능력치 성장매치마다 1레벨
부상·포로매치 안에서만

매치마다 명부에서 5명이 출전합니다. 능력치는 무력·통솔·내정·기동 4종입니다.

등급과 격차 완화

  • 1~5성(별 개수). 레벨당 상승폭은 획득 등급 기준으로 평생 유지
  • 유대 승급: 출전 기록과 훈련(주간 상한)으로 5성까지. 돈으로 살 수 없음
  • 아웃라이어: 등급보다 높은 숨은 성장 계수. 낮은 등급일수록 확률이 높고 첫 승급 때 공개
  • 6~7성: 특수 조건에서만 승급(조건 미정)

첫 프로토타입이 증명할 가설

가설확인 방법
A. 세팅 차이가 결과 차이로 드러난다같은 모델, 다른 세팅 프리셋끼리 대전
B. 모델 격차를 보고서 예산 계수로 좁힐 수 있다강·약 모델 대전, 계수를 바꾸며 승률 변화 측정
C. 메모와 전쟁 일지가 읽을 만한 이야기를 만든다매치 후 사용자가 일지를 읽고 판정
D. 등급이 순위를 결정하지 않는다출전 영웅 평균 별 수와 순위의 상관
E. LLM 참모가 규칙 참모보다 확실히 낫다기준선 대비 승률

결정 로그

#결정근거
1참모 하나만 AI, 영웅은 규칙 기반 실행자호출량이 영웅 수에 비례하지 않아 구독 한도 안에 들고, 영웅 간 협조가 쉽다.
2소규모 매치(6명, 1시간 × 5일)AI 운용 실력 차이가 결과에 잘 드러나고, 밸런스 조정 주기가 빠르다.
3거점 과반 12턴 유지로 조기 승리 + 점수 순위경기가 반드시 끝나 호출량이 예측되고, 저지를 위한 외교가 살아난다.
4턴 시작에 계획, 마감까지 검토, 수동 재계획 하루 3회세팅을 바꿔 보고 결과를 같은 턴에 확인하는 튜닝 고리가 핵심 실력이다.
5자동 긴급 호출 기각상시 명령과 겹치고, 턴 처리 중 호출 대기로 서버 처리가 복잡해진다.
6정보 구성만 길이 예산으로 제약무엇을 보여 줄지 고르는 것이 모델과 맞물린 AI 운용 실력이 되고, 호출당 비용도 예측된다.
7보고서 예산은 매치 안 정보 건물로만 증가과금·등급이 AI 운용 축에 들어가지 않게 한다.
8참모 메모·조건부 명령·전쟁 일지 도입기억·의도·보이는 판단이 있어야 실제 AI 지휘관끼리의 전쟁으로 느껴진다.
9정형 외교만, 배신은 벌칙 없이 약속 기록 공개프롬프트 인젝션이 구조적으로 막히고, 신뢰 판단을 AI와 사람에게 맡긴다.
10등급제(1~5성) + 유대 승급 + 숨은 아웃라이어BM의 축을 두되 시간과 운으로 격차를 좁혀 pay-to-win을 완화한다.
11빈자리는 저가 모델 봇, 최소 1명이면 매치 시작초기 유저가 적을 때와 AI와 겨루는 플레이를 함께 해결한다. 봇 비용은 운영자가 부담한다.
12모델별 보고서 예산 계수 + 매치 기록으로 밸런스규칙은 그대로 두고 맥락만 조절하므로 공정성을 설명하기 쉽다.

다음 Phase 권장

다음 S1 시뮬레이션 프로토타입 설계

서버·계정·클라이언트 없이 규칙 엔진, 빠른 턴 모드, 규칙 참모, LLM 참모(봇)만으로 6인 매치를 통째로 돌려 가설 A·B·D·E를 측정하고, 전쟁 일지로 가설 C를 판정합니다. 설계에서는 개발 언어와 LLM 호출 방식, 프롬프트 템플릿과 출력 형식, 첫 맵 1장과 수치 초안을 정합니다.

순서 근거: 가설 A·E가 깨지면 게임 자체가 성립하지 않으므로, 비용이 큰 서버·연동 설계보다 먼저 확인합니다. 프로토타입에서 실측한 호출당 토큰은 구독 연동 가능성과 봇 비용 판단의 근거가 됩니다.

향후: 기술 설계(서버, 계정·구독·API 키 연동, 클라이언트), 웹 클라이언트·관전 화면, 영웅 명부·BM.
