설계 승인 작성일: 2026-10-27

요약

서버·계정·클라이언트 없이 로컬에서 도는 시뮬레이션 코어와 빠른 턴 모드를 설계했습니다. 게임 규칙 설계서의 가설 A~E를 측정할 도구를 만드는 데까지가 범위입니다.

매치 규칙 전체를 순수 TypeScript 코어로 만들고, 턴 처리는 processTurn 순수 함수, 참모는 비동기 인터페이스로 둡니다. 시드와 LLM 원문 기록으로 매치를 재현하고, 나중에 실서버와 다중 플랫폼 클라이언트가 같은 코어를 재사용합니다.

LLM 참모는 개발자 본인 구독의 claude -p 헤드리스로 부르고, 호출량은 실행마다 자리 구성과 턴 수로 조절합니다. 결과는 매치 기록·Markdown 보고서·배치 요약 표로 봅니다.

한 매치의 데이터 흐름

실행 설정→ initState→ 참모 호출(6자리 동시)→ 검증·대체→ 제약 적용·확정→ processTurn→ 새 상태 + 이벤트
새 상태 + 이벤트→ 조기 승리 / 남은 자리 1 / 턴 수 도달→ 종료·점수 순위

종료 조건이 아니면 참모 호출로 돌아갑니다. 무작위는 모두 (매치 시드, 턴, 자리)에서 나오고, 비결정적인 LLM 응답은 원문을 기록해 재생합니다. 턴별 전체 상태 스냅샷은 저장하지 않습니다.

LLM 호출부

구현내용
claude -p 어댑터--output-format json --json-schema --system-prompt-file --tools "" --no-session-persistence --model, 보고서는 stdin. --bare는 구독 인증을 읽지 않아 쓰지 않음
가짜시드로 정상·깨진 출력을 냄. 테스트용
기록 재생(턴, 자리)의 원문 응답 반환

확인한 것 (2026-10-27, Claude Code 2.1.291)

  • 확인 structured_output에 스키마에 맞는 JSON, usage에 토큰
  • 확인 haiku 1회 약 7초
  • 확인 stdin 입력, --system-prompt-file
  • 미확인 구독 한도 실제 횟수, 한도 소진 오류 문구

프롬프트와 실패

  • 프롬프트·메모·전쟁 일지 모두 영어(월드 서버)
  • 출력 스키마는 zod 한 벌에서 JSON Schema로 변환
  • 길이 예산은 결정적 근사(글자 수 비례)로 세고 실제 토큰은 기록만
  • 재시도 없음. 실패율이 기준을 넘은 매치는 무효, LLM 자리 전부 연속 실패 시 배치 중단

CLI와 출력물

CLI

명령하는 일
run매치 하나
batch실험 파일의 변형 × 매치 수

출력물 (runs/, git 제외)

  • match.json: 매치 기록
  • report.md: 순위, 턴별 요약, 주요 이벤트, 전쟁 일지·메모 전문, 대체 통계
  • summary.md: A 프리셋별 순위, B 모델 × 계수 승률, D 별 수-순위 상관, E LLM 대 규칙 참모, 무효 수

C는 사용자가 report.md를 읽고 판정합니다.

완료 기준

  1. 규칙 참모 6명 120턴 결정적 완주 + report.md
  2. claude -p LLM 참모 매치 완주, 실패·대체 기록
  3. batch가 A·B·D·E 요약 표 생성
  4. replay가 같은 결과 재현
  5. LLM 매치 report.md로 가설 C 판정 가능

실제 claude -p 호출은 자동 테스트에 넣지 않고 수동 스모크로 확인합니다. 가설의 참·거짓 판정은 완료 기준이 아닙니다.

결정 로그

#결정근거
1기술 설계를 하위 프로젝트 5개로 분해, 코어 먼저가설 A·E가 깨지면 게임이 성립하지 않으므로 서버·클라이언트보다 먼저 확인한다.
2클라이언트는 PC·모바일 등 다중 플랫폼사용자 결정.
3TypeScript(Node 24)UI 중심 장르라 웹 기술 클라이언트가 자연스럽고, 코어·서버·클라이언트가 타입과 검증을 공유한다.
4월드 서버, 프롬프트·메모·일지 모두 영어모든 플레이어·모델에 같은 템플릿이라 공정하고, 상대 일지는 다른 나라 플레이어에게도 공개된다.
5순수 턴 함수 + 비동기 참모 구조재현·서버 이전·클라이언트 표시·분석에 모두 그대로 재사용된다. 가변 객체·이벤트 소싱은 기각.
6매치 규칙 전부, 사람 조작·메타 제외빠른 턴 모드는 봇만 돌리므로 사람 조작이 쓰이지 않고, 가설 A가 빠진 규칙으로 왜곡되지 않게 한다.
7호출량은 자리 구성 + 턴 수로 실행마다 조절가설마다 필요한 구성이 다르고, 구독 한도 안에서 측정해야 한다.
8실험에서도 재시도 없음, 대체 많은 매치는 무효 표시측정 조건을 실제 게임 규칙과 같게 유지한다.
9결과는 JSON 기록 + Markdown, 화면 없음첫 범위에 화면 작업을 넣지 않는다.
10zod로 스키마 한 벌TS 타입·런타임 검증·--json-schema 입력을 한 정의에서 얻고, 브라우저에서도 재사용한다.
