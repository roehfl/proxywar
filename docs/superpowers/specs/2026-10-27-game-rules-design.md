# proxywar 게임 규칙 설계 (첫 설계)

- 날짜: 2026-10-27
- 상태: 승인(2026-10-27)
- 전제: `docs/design/brainstorm-log.md`의 확정 결정. 이 문서의 결정도 같은 기록에 옮겨 두었다.
- 범위: 게임 규칙(경기 구조, 맵·자원·군사, 참모 AI와 세팅, 외교, 영웅, 직접 플레이, 밸런스·BM). 기술 설계(서버, 계정·구독·API 키 연동, 클라이언트)는 별도 문서로 쓴다.

## 0. 한 문단 요약

마스터 6명이 1시간 턴으로 5일 동안 겨루는 서버 턴제 전쟁 시뮬레이션이다. 마스터는 프롬프트를 쓰지 않고, 세팅값(boolean·1~5)과 영웅 구성으로 자기 참모 AI를 조율한다. 참모는 턴마다 한 번 호출되어 영웅 5명의 임무, 거점 운영, 외교를 정하고, 다음 턴의 자신에게 메모를 남기며, 판단 근거를 전쟁 일지로 쓴다. 마스터는 검토 시간 동안 계획을 고치거나 세팅을 바꿔 재계획할 수 있고, 탐험으로 직접 플레이한다. 영웅은 1~5성 등급이 있고, 오래 함께하면 승급하며, 낮은 등급에서 숨은 아웃라이어가 나온다. 경쟁력은 "AI를 얼마나 잘 쓰느냐"(세팅·정보 구성)와 모델 성능이고, 모델 격차는 보고서 예산 계수로 조정한다.

## 1. 경기 구조와 턴 흐름

### 매치
- 마스터 6명, 1시간 턴 × 5일 = 120턴.
- 최소 사람 1명이면 매치가 열린다. 빈자리는 저가 모델 봇이 채운다(1.4).
- 승리는 단독으로만 한다. 동맹은 일시적이다.

### 승리와 탈락
- **조기 승리**: 전체 거점의 과반을 12턴 연속 보유.
- **기간 종료**: 120턴 뒤 점수로 순위를 매긴다. 점수는 보유 거점·거점 발전도·영웅 성장 등의 합이고, 공식은 프로토타입에서 정한다.
- **수도 함락**: 남은 거점 하나로 수도를 옮기고 큰 손실을 입는다.
- **탈락**: 거점이 0개가 되면 탈락하고, 그 시점의 점수로 순위가 정해진다.

### 1.1 한 턴의 흐름 (정각 T 기준)
1. **T 처리**: `이동 → 조건 판정·반응 → 전투 → 생산·성장 → 외교 정산`. 처리 중에는 AI를 호출하지 않는다.
2. **처리 직후**: 참모 정기 호출 1회. 이번 턴 계획을 받는다.
3. **검토 시간(약 55분)**: 마스터는 다음 중 무엇이든 할 수 있다.
   - 아무것도 안 함 → 계획대로 진행
   - 명령 직접 수정(호출 아님)
   - 세팅 변경 후 수동 재계획(호출 1회)
4. **T+55분 마감**: 명령 확정. 다음 정각에 1로 돌아간다.

### 1.2 호출량
- 정기 호출: 턴당 1회(매치당 120회).
- 수동 재계획: 하루 3회 충전, 이월 없음(매치당 최대 15회).
- 실패한 호출(타임아웃·형식 오류·한도 소진)은 재시도하지 않고 규칙 참모로 대체한다.
- 세팅 변경은 호출이 아니며, 다음 호출부터 반영된다.
- → **마스터당 매치 최대 135회로 고정**. 구독 사용량을 미리 알 수 있다.
- 자동 긴급 호출(턴 처리 중 추가 호출)은 두지 않는다. 턴 중간 반응은 조건부 명령(3.4)이 맡는다.

### 1.3 규칙 참모
LLM 없이 세팅값대로 계획을 내는 내장 참모다. 다음 경우에 쓴다.
- AI를 연결하지 않은 마스터가 직접 입력하지 않은 턴
- LLM 호출이 실패한 턴(계획 전체), 또는 계획의 잘못된 항목
- LLM 참모의 실력을 재는 기준선

### 1.4 봇
- 빈자리를 채우는 저가 모델 LLM 참모다. **호출 비용은 운영자가 부담**한다(봇 5명이면 매치당 약 600회. 저가 모델 단가는 미확인).
- 세팅 프리셋(공격형·내정형·외교형 등)으로 성격을 다르게 한다.
- 수동 재계획과 직접 플레이는 하지 않는다. 외교에는 똑같이 참여한다.

## 2. 맵·자원·군사

### 맵
- 거점 30개 안팎을 길로 이은 **노드 그래프**. 거점 종류는 도시·요새·자원지 등이다.
- 마스터마다 수도 1개에서 출발한다. 손으로 만든 6인용 맵 몇 장 중 하나를 쓴다.
- 참모에게는 거점 목록, 인접 관계, 각 거점 상태를 글로 넘긴다.

### 자원
| 자원 | 주 용도 |
|---|---|
| 금 | 거점 발전, 영웅 육성 |
| 식량 | 병력 모집, 병력 유지비(턴마다 차감) |
| 자재 | 건설, 요새화 |
| 희귀 자원 | 영웅 고급 성장, 특수 건물. 특정 거점에서만 생산 |

거점마다 생산 비중이 달라 교환할 동기가 생긴다.

### 거점 발전
건물 분류는 생산·모집·방어·정보다. **정보 건물**(참모부·첩보망 등)은 보고서 길이 예산을 늘린다(3.2).

### 군사
- 병력은 거점에서 모집하고, **영웅이 부대를 이끌어** 이동·공격한다. 영웅이 없는 거점에는 수비대만 둔다.
- 전투력 = 병력 수 × 영웅 능력치 보정 × 지형 보정(요새 등).
- 전투는 정각 처리 때 결정적 규칙에 작은 무작위 폭을 더해 정산한다.

### 시야
자기 거점과 영웅 주변만 보인다(전장의 안개). 정찰과 첩보 건물, 탐험(6.1)으로 넓힌다. 참모가 받는 정보도 시야 안으로 한정된다.

## 3. 참모 AI와 세팅

### 3.1 프롬프트 조립
게임이 템플릿에 `게임 규칙 설명 + 성향 문구 + 지침 + 선택한 정보 + 참모 메모 + 출력 형식`을 채운다. 템플릿은 개발자가 관리하고 모든 모델에 같은 것을 쓴다.

### 3.2 세팅
| 종류 | 값 | 예시(첫 목록, 플레이테스트로 조정) | 작동 |
|---|---|---|---|
| 성향 | 1~5 | 공격성, 확장 욕구, 위험 감수, 동맹 신의, 내정↔군사 비중, 보복 성향 | 프롬프트의 방향 문구 |
| 지침 | boolean | 식량 부족 시 모집 자제, 희귀 자원지 우선, 약한 상대 우선 | AI에게 알리기만 하고 강제하지 않음 |
| 안전장치 | boolean·기준값 1~5 | 수도 최소 수비(1~5), 동맹 공격 금지 | 게임이 강제(3.6). 소수로 유지 |
| 정보 구성 | on/off + 상세도 1~5 | 시야 내 적 병력, 적 이동 기록, 외교 이력, 지난 턴 결과, 영웅 상세, 순위표, 탐험 보고, 참모 메모 길이 | 켠 항목만 보고서에 들어가고, 길이 예산을 씀 |
| 영웅별 상시 명령 | boolean·1~5 | 수도 방어 전담, 후퇴 기준(1~5), 원정 허용 | 게임이 강제(3.6) |

- 성향·지침·안전장치·상시 명령은 자유롭게 정하고, 제약은 정보 구성에만 둔다.
- 내 거점 현황과 영웅 위치 같은 필수 정보는 항상 들어가고, 예산을 쓰지 않는다.
- **보고서 길이 예산**: 모든 마스터가 같은 값에서 시작하고, 정보 건물로 늘어나며, 모델별 계수(7.1)를 곱한다. 내부 단위는 토큰이고, 화면에는 "칸"으로 보인다.

### 3.3 참모 메모
참모는 호출마다 다음 호출의 자신에게 메모를 남긴다. 메모는 다음 보고서에 들어가고, 정보 구성에서 고른 길이로 잘린다. 여러 턴짜리 전략과 상대 평가를 이어 가는 장치다.

### 3.4 조건부 명령
임무 하나에 조건 하나를 붙일 수 있다. 턴 처리의 "조건 판정·반응" 단계에서 실행된다. 추가 호출은 없다.
- 조건: 적 접근, 대상 거점이 빔, 병력 비율, 아군 거점 피습
- 반응: 후퇴, 진격, 증원, 방어

### 3.5 출력과 검증
참모의 출력은 정해진 형식이다.
- 영웅별 임무(이동·공격·방어·거점 운영 중 하나 + 대상 + 선택 조건)
- 거점별 건설·모집
- 외교 제안과 받은 제안에 대한 응답
- 참모 메모
- 전쟁 일지: 정세 판단과 이유. 길이 상한은 게임이 고정한다. 내 일지는 실시간으로, 상대 일지는 매치 종료 뒤 공개한다.

잘못된 항목은 그 항목만 규칙 참모의 판단으로 바꾼다. 형식이 통째로 깨지면 계획 전체를 규칙 참모가 대신한다.

### 3.6 명령 확정 순서
1. **마스터 직접 수정**: 모든 제약보다 앞선다.
2. **제약**(영웅별 상시 명령 + 안전장치): 함께 적용되고, 참모 계획이 어기면 게임이 고친다. 예를 들어 "레아: 수도 방어 전담"이면 레아에게 내려진 공격 임무를 막고, "수도 최소 수비 3"이면 출격 병력에서 기준만큼 수도에 남긴다.
3. **참모 계획**: 제약 안에서 자유롭게 정한다.

참모도 제약을 보고서로 미리 받으므로, 대부분은 처음부터 지키는 계획을 낸다.

## 4. 외교

- **관계**: 마스터 둘 사이는 `전쟁 · 중립 · 불가침 · 동맹` 중 하나이고, 시작은 중립이다.
- **정형 제안**(자연어 메시지 없음):

| 제안 | 내용 |
|---|---|
| 불가침 | 정한 턴 수 동안 서로 공격 금지. 턴 수는 제안할 때 정해진 선택지(예: 12·24·48턴) 중에서 고른다 |
| 동맹 | 서로 공격 금지 + 시야 공유 + 거점 통과 허용 |
| 자원 교환 | 자원 종류·양을 맞바꿈(1회) |
| 포로 교환 | 포로 영웅 맞교환, 또는 자원을 받고 반환 |
| 선전포고 | 관계를 전쟁으로(일방 통보) |
| 파기 | 불가침·동맹 해제(일방 통보) |

- **흐름**: 참모 계획이나 마스터 직접 조작으로 제안 → 외교 정산 때 전달 → 받은 쪽이 다음 계획이나 직접 조작으로 수락·거절 → 다음 정각까지 응답이 없으면 만료.
- **배신**: 파기와 기습을 허용하고, 규칙상 벌칙은 없다. 누가 언제 어떤 약속을 깼는지 **약속 기록**을 모두에게 공개하고, 참모는 정보 구성의 "외교 이력"으로 읽는다.
- "동맹 공격 금지" 안전장치가 켜져 있으면, 참모는 파기를 먼저 해야 동맹을 공격할 수 있다. 파기는 통보 즉시 효력이 생기고, 공격은 다음 턴부터 가능하다.

## 5. 영웅

### 5.1 명부 (계정에 남는 것)
보유 영웅, 각 영웅의 고유 특성, 등급, 유대, 숨은 성장 계수. 레벨·능력치 성장은 매치마다 새로 시작한다.

### 5.2 등급
- **1~5성**(별 개수). 획득 등급은 1~5성 중 하나다.
- 등급이 결정하는 것: 레벨당 능력치 상승폭(**획득 등급 기준, 평생 유지**), 레벨 상한, 특성 슬롯 수.
- **6~7성**: 특수한 조건에서만 승급할 수 있다. 조건은 열린 질문이다.

### 5.3 능력치와 특성
- 능력치 4종: 무력(전투), 통솔(이끌 수 있는 병력과 부대 보정), 내정(거점 운영), 기동(이동·정찰).
- 특성(1~5): 충성, 신중, 용맹 등. 영웅은 AI가 아니라 **규칙 기반 실행자**이고, 특성이 임무 수행에 반영된다. 예를 들어 충성이 낮으면 일정 확률로 명령에서 벗어나고, 신중이 높으면 불리할 때 스스로 물러난다.

### 5.4 매치 안 성장
- 매치마다 레벨 1에서 시작하고, 임무(전투·거점 운영·탐험)로 경험치를 얻는다.
- 레벨업 상승폭 = `획득 등급 기준값 × 숨은 성장 계수 × 무작위 폭`.

### 5.5 아웃라이어
- 숨은 성장 계수가 등급 기준보다 높은 영웅이다. **낮은 등급일수록 나올 확률이 높다.**
- 겉으로 표시되지 않고, 무작위 폭 때문에 레벨업 몇 번으로는 확신할 수 없다. 매치 밖 훈련의 성장 편차가 단서가 된다(6.2).
- **첫 승급 때 정체가 공개**된다.

### 5.6 유대와 승급
- 유대는 끝까지 함께한 출전 매치 수와 매치 밖 훈련(주간 상한)으로 쌓인다.
- 유대 단계가 차면 한 단계 승급할 수 있다(일반 상한 5성). 승급하면 레벨 상한과 특성 슬롯이 오르지만, 상승폭은 획득 등급 기준 그대로다.
- 그래서 오래 함께한 영웅은 격차를 좁히지만, 같은 레벨의 타고난 고등급을 넘지는 못한다. 아웃라이어는 예외다.

### 5.7 출전과 패배
- 매치마다 명부에서 5명을 고른다. 같은 영웅을 동시에 두 매치에 출전시킬 수 없다.
- 패한 영웅은 부상(몇 턴 이탈)이나 포로가 된다. 포로는 포로 교환 대상이다. 매치가 끝나면 모두 돌아오고, 명부와 유대에는 영향이 없다.
- 획득 경로: 매치 보상, BM(7.3).

## 6. 직접 플레이

원칙:
- 마스터가 직접 할 때만 일어난다. 참모 AI와 봇은 하지 않는다.
- 하루 상한이 있다.
- 결과는 참모가 쓸 재료(정보·자원·영웅 상태)가 된다.

### 6.1 매치 안: 탐험
- 탐험권은 하루 2회 충전되고, 이월되지 않는다.
- 영웅 1명을 안개 밖 인접 구역으로 보낸다. 영웅은 3턴 동안 자리를 비우고, 그동안 참모는 그 영웅을 쓸 수 없다.
- 진행은 턴마다 이벤트 로그로 볼 수 있다.
- 결과(영웅의 기동·무력과 무작위 폭으로 결정):
  - 정보: 안개 밖 거점 상태·병력, 희귀 자원지 위치. 정보 구성의 "탐험 보고"로 참모 보고서에 들어간다
  - 소량의 자원이나 희귀 자원
  - 탐험한 영웅의 경험치
  - 사건: 중립 세력 합류, 부상 등

### 6.2 매치 밖: 영웅 훈련
- 출전 중이 아닌 영웅을 훈련시킨다. 훈련권은 하루 3회다.
- 훈련 1회마다 유대가 조금 쌓이고, 훈련으로 쌓는 유대에는 주간 상한이 있다.
- 훈련 결과에 성장 편차가 보이고, 아웃라이어는 편차가 크게 나온다.

### 6.3 미니게임
도입하지 않는다. 전체 밸런스를 잡은 뒤 다시 검토한다.

수치(하루 2회, 3턴, 하루 3회)는 첫 값이고, 플레이테스트로 조정한다.

## 7. 밸런스와 BM

### 7.1 모델 밸런스
- **지원 모델 목록제**: 서버는 등록된 모델만 호출하고, 모델마다 보고서 예산 계수를 둔다. 강한 모델은 계수가 작다.
- **기록**: 매치마다 모델별 순위, 승률, 호출 실패율, 평균 입출력 길이. 규칙 참모와 봇의 성적은 기준선이다.
- **조정**: 일정한 주기(예: 주 단위)로 계수를 바꾸고 공지한다. 매치 도중에는 바꾸지 않는다.

### 7.2 과금과 AI 운용의 분리
보고서 예산, 호출 횟수, 세팅 항목처럼 AI 운용에 닿는 것은 팔지 않는다. 예산은 매치 안 거점 발전으로만 늘어난다.

### 7.3 BM과 등급
- 등급제(1~5성)가 BM의 축이다. 판매 방식은 열린 질문이다.
- pay-to-win 방지 장치: 유대 승급(시간으로 5성까지, 돈으로 살 수 없음), 낮은 등급일수록 높은 아웃라이어 확률, 매치 밖 훈련 상한.
- 같은 매치 안 등급 격차의 허용 범위는 "출전 영웅 평균 별 수와 순위의 상관" 지표로 정한다.

## 8. 범위 밖, 열린 질문, 검증

### 이 문서에서 다루지 않는 것
- 기술 설계: 서버 구성, 계정·구독·API 키 연동과 보관, 클라이언트 플랫폼
- 수치 표: 전투 공식, 생산량, 경험치 곡선, 점수 공식, 등급별 상승폭

### 열린 질문
- 미니게임 도입 여부
- 6~7성 승급 조건
- BM 상세(무엇을 어떻게 파는가)
- 같은 매치 안 등급 격차의 허용 범위
- 자동 긴급 호출 재도입 여부(조건부 명령으로 부족할 때)
- 기만 행동(위장 이동·허위 병력)
- 구독 연동 경로(OpenAI "Sign in with ChatGPT" 파트너 조건, 미확인), 봇용 저가 모델 단가(미확인)

### 첫 프로토타입이 증명할 가설
| 가설 | 확인 방법 |
|---|---|
| A. 세팅 차이가 결과 차이로 드러난다 | 같은 모델, 다른 세팅 프리셋끼리 붙여 순위가 갈리는지 |
| B. 모델 격차를 보고서 예산 계수로 좁힐 수 있다 | 강·약 모델을 붙이고 계수를 바꿔 가며 승률 변화를 봄 |
| C. 참모 메모와 전쟁 일지가 읽을 만한 "전쟁 이야기"를 만든다 | 매치 후 일지를 사용자가 읽고 판정 |
| D. 등급이 순위를 결정하지 않는다 | 출전 영웅 평균 별 수와 순위의 상관 |
| E. LLM 참모가 규칙 참모보다 확실히 낫다 | 기준선 대비 승률. 아니면 AI를 연결할 이유가 없다 |

### 빠른 턴 모드
1시간을 기다리지 않고 턴을 연속으로 처리하는 시뮬레이션 모드를 둔다. 봇 6명으로 매치를 통째로 돌려 가설 A·B·D·E를 반복 측정한다. 첫 구현 범위에 넣는다.
